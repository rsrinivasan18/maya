## Bug Fix — Markdown in LLM Responses

### Problem
MAYA was using **bold text** and other markdown in responses, violating
the "plain conversational text only" rule. The no-markdown instruction in
`base.md` was being ignored by the LLM.

### Root Cause
Prompt file instructions alone are unreliable for format constraints —
large models (Claude sonnet) follow them at inference time but not
consistently across all response types.

### Fix (hello_world_graph.py)

**Two-layer defence:**

1. `_NO_MARKDOWN` constant injected into `system_content` at runtime in
   `math_tutor_response` and `help_response`. Hard-coded in Python, not
   in a .md file — ensures it appears in every single call regardless of
   which prompt file loads.

2. `_strip_markdown(text)` post-processor applied to every LLM response
   before returning from the node:
   - `**bold**` / `*italic*` / `__underline__` → plain text
   - `## headers` → plain text
   - `- bullet` / `* bullet` → plain text
   - `1. numbered lists` → plain text
   - `` `inline code` `` → plain text
   - `---` horizontal rules → removed
   - Excess blank lines collapsed

`greet_response` and `farewell_response` use hardcoded strings — no LLM,
no strip needed.

**57/57 tests passing after change.**

## Bug Fix — Three Production RoboEyes Bugs

### Bug 1 — Eyes showing yellow after math responses

**Symptom:** Eyes change from cyan to yellow/gold when Srinika asks maths.

**Root Cause:**
- `INTENT_DONE_STATE.math = 'celebrating'`
- `celebrating` state color = `[255, 215, 0]` (gold)
- So after every math response: intent=math → state=celebrating → eyes go yellow

**Fix (maya_eyes.js):**
```
celebrating: [0, 230, 255]   // vivid cyan  (was gold [255, 215, 0])
excited:     [0, 220, 255]   // bright cyan (was yellow [255, 210, 50])
```
All 12 states now use cyan variants. Eyes are always cyan — MAYA's identity
colour. Emotional expression comes from blink timing, pupil movement, mouth
shape, and blush — not colour changes.

### Bug 2 — Face pushed to right side of screen

**Symptom:** RoboEyes face visually off-centre, shifted right, on both
desktop and mobile production URL.

**Root Cause:**
- `#maya-p5-canvas` was a plain block div
- p5.js `createCanvas()` appends a `<canvas>` element inside it
- Block div with no explicit alignment = canvas left-aligned by default
- `#maya-hero` flex-centres `#maya-eyes-container`, but the canvas inside
  `#maya-p5-canvas` was not centred within its own container

**Fix (style.css):**
```css
#maya-p5-canvas {
  display: flex;
  justify-content: center;
  width: 100%;
}
#maya-p5-canvas canvas {
  display: block;
  margin: 0 auto;
}
```
Double centring: flex container + margin auto. Belt and braces.

**Lesson:** p5.js `canvas.parent('id')` appends the canvas as a child of
the div but does not centre it. Always explicitly centre the canvas wrapper.

### Bug 3 — Avatar freezes and stops animating

**Symptom:** RoboEyes occasionally freeze mid-expression on mobile and
App Runner. Face stops moving entirely. Only a page refresh fixes it.

**Root Cause:**
p5.js `draw()` loop can silently stop when:
- Page tab goes background then foreground (browser throttles RAF)
- App Runner's Envoy proxy idle timeout disconnects something
- JavaScript error in draw() causes p5 to call `noLoop()` internally
- Mobile browser lifecycle management pauses the animation frame

**Fix (maya_eyes.js):**
```javascript
// Watchdog — restarts draw loop if frozen for 10s
let lastDrawMs = Date.now();
setInterval(function() {
  if (Date.now() - lastDrawMs > 10000) {
    p.loop();  // restart if draw() hasn't run in 10 seconds
  }
}, 5000);

// In p.draw():
p.draw = function() {
  lastDrawMs = Date.now();   // heartbeat
  p.clear();
  ...
}
```

`setInterval` checks every 5s. If `draw()` hasn't stamped `lastDrawMs` in
10s, calls `p.loop()` to restart. Completely silent to the user — face just
continues animating as if nothing happened.

**Why 5s check / 10s threshold:** A blink cycle is ~140ms, idle micro-jitter
runs every 200–800ms. If draw() is running normally, `lastDrawMs` is always
< 100ms old. 10s is far beyond any normal pause — only fires on genuine freeze.

## Key Learnings

### On LLM instruction reliability
Prompt file instructions are "suggestions" to the LLM. Format constraints
(no markdown, max 3 sentences) need to be enforced twice:
1. Injected in Python code (not .md files) — harder for LLM to "forget"
2. Post-processed in code — catches anything the LLM still produces

### On p5.js canvas centering
`canvas.parent('id')` appends the canvas inside the div, but doesn't
centre it. The parent div needs `display:flex; justify-content:center`.
This is especially important when the canvas size is dynamic (responsive).

### On p5.js stability in cloud environments
App Runner + mobile browsers both throttle or suspend RAF (requestAnimationFrame).
p5.js wraps RAF internally and can silently enter `noLoop()` state.
Any long-running p5 sketch deployed to cloud/mobile needs a watchdog.

### On colour-based emotion states
Using colour to express emotion (yellow for celebrating, red for angry)
looks inconsistent when the character has an established identity colour.
For MAYA: cyan = MAYA's identity. All states use cyan variants — expression
via shape/movement only.
